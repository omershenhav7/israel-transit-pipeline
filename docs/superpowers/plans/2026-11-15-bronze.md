# Bronze Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** load the six schedule files of each landed GTFS zip into raw, all-text Delta tables on S3, one Airflow task and one `spark-submit` per table.

**Architecture:** the logic lives in `src/transit/bronze.py` (plain functions, tested with local Spark and local Delta paths). `src/transit/jobs/bronze.py` is the `spark-submit` entry point for one table and one day. A new DAG, `gtfs_build`, starts on the `gtfs_landing` Asset event and runs six `@task.bash` tasks in a 1-slot `spark` pool.

**Tech Stack:** PySpark 4.2.0, delta-spark 4.4.1, Airflow 3.3.2 (LocalExecutor), boto3, pytest. Everything runs in the `transit-airflow:latest` image.

**Spec:** [`docs/stage-2-bronze.md`](../../stage-2-bronze.md)

## Global Constraints

- The six tables are `agency`, `calendar`, `routes`, `stops`, `stop_times`, `trips`, with the expected columns from the spec's table, in that order.
- Every data column is `string` and keeps its original GTFS name. There's no typing, renaming or filtering.
- Extra columns: `feed_date` (`date`, the partition column), `_source_file` (the landing key, `landing/gtfs/feed_date=YYYY-MM-DD/gtfs.zip`) and `_loaded_at` (`timestamp`).
- Table path: `lakehouse_path("bronze", table)`, i.e. `s3a://<bucket>/bronze/<table>/`.
- Writes use `replaceWhere feed_date = '<date>'`.
- Retention: delete partitions whose `feed_date` is more than 7 days before today in Israel (`Asia/Jerusalem`), except the day just loaded, then `VACUUM` with the default retention.
- Read options: quote handling off (`quote` = `\u0000`), `mode=FAILFAST`, no schema inference.
- One Spark job at a time: the `spark` pool has 1 slot.
- Tests need no network or AWS. Spark tests write Delta to `tmp_path`.
- Tests run in the image, because this Windows machine has no Java:
  `docker compose run --rm -v "$PWD/tests:/opt/airflow/tests" airflow-cli bash -c "pip install -q pytest && python -m pytest -q /opt/airflow/tests"`.
  Run this on the VM, from `~/israel-transit-pipeline`, after copying or pulling the branch there.
- Work on a branch, `stage-2-bronze`. Commit after each task. Don't push without asking.

## Review Focus

1. **A row with fewer fields than the header.** Under FAILFAST, Spark may pad the row with nulls instead of failing. The expected behaviour is that the load fails. Test: `test_short_row_fails` in Task 2.
2. **Empty fields.** Spark reads an unquoted empty field as null, not `""`. That's accepted (*plan's call*: GTFS doesn't distinguish the two), but it must be the same every time. Test: `test_empty_field_is_null` in Task 2.
3. **More than one Asset event in one `gtfs_build` run** (Airflow merges queued events), for example after the scheduler was down. Expected: fail clearly rather than load only one day silently. Test: `test_resolve_feed_date_rejects_two_days` in Task 5.
4. **`spark-submit` ignoring JVM settings set in Python.** Driver memory, the AWS SDK classpath, the packages and the Ivy cache must come from the command line. Test: `test_spark_submit_command_carries_jvm_settings` in Task 4. The real check is the VM run in Task 6.
5. **A hand-rebuilt old day** (more than 7 days back) must not delete newer partitions, and must survive its own load. Test: `test_cleanup_keeps_old_day_just_loaded` in Task 3.

### Task 4: The job and its `spark-submit` command

**Files:**
- Modify: `src/transit/bronze.py`

- Create: `src/transit/jobs/__init__.py`
- Create: `src/transit/jobs/bronze.py`
- Create: `tests/test_bronze_job.py`

**Interfaces:**
- Consumes: everything above, `landing.zip_key(feed_date: date) -> str` from `src/transit/landing.py`, and `get_spark` and `lakehouse_path` from `src/transit/spark.py`
- Produces:
  - `build_bronze_table(spark, s3, bucket: str, table: str, feed_date: date, today: date, table_path: str | None = None) -> int`. It downloads the zip with `s3.download_file(bucket, zip_key(feed_date), local_path)` into a `tempfile.TemporaryDirectory`, then runs `extract_table`, `check_header`, `load_table` (with `source_key=zip_key(feed_date)` and `loaded_at` set to now in Israel) and `cleanup(..., today, feed_date)`. It returns the rows written. A missing zip (S3 `404` from `download_file`) raises `BronzeLoadError("no zip in landing for <date>")`.
  - `spark_submit_command(script: str, *args: str) -> list[str]` in `spark.py`. It starts with `spark-submit --master local[*]` and includes `--driver-memory` (from `SPARK_DRIVER_MEMORY`, default `4g`), `--packages` with the Delta package (`io.delta:delta-spark_4.2_2.13:4.4.1`) and `HADOOP_AWS`, and `--conf spark.jars.ivy=$SPARK_IVY_DIR` when that variable is set. When `AWS_SDK_BUNDLE` is set, it also includes `--exclude-packages software.amazon.awssdk:bundle` and `--driver-class-path $AWS_SDK_BUNDLE`. Then come `script` and `args`. Take the Delta coordinate from the same place `configure_spark_with_delta_pip` gets it, or keep it as a constant next to `HADOOP_AWS`, so it isn't written twice.
  - `src/transit/jobs/bronze.py`: `main(argv: list[str] | None = None) -> int` with `--table` (one of `TABLES`) and `--feed-date YYYY-MM-DD`. It calls `build_bronze_table(get_spark(f"bronze_{table}"), boto3.client("s3"), os.environ["GTFS_BUCKET"], ...)` with today in Israel, prints the row count and returns 0. It ends with `sys.exit(main())` under `__main__`.

### Task 5: The `gtfs_build` DAG and the `spark` pool

**Files:**

**Interfaces:**
- Consumes: `GTFS_LANDING` from `src/transit/assets.py` (events carry `extra={"feed_date": "YYYY-MM-DD"}`), `TABLES`, and `spark_submit_command`
- Produces:
  - `resolve_feed_date(events: list[dict], param: str | None) -> str` in `src/transit/bronze.py`. It takes the `extra` dicts of the triggering events plus the manual `feed_date` param, and returns one ISO date. It raises `ValueError` when there are none, or when the events name more than one date. A param wins over events.
  - `dags/gtfs_build.py`: `schedule=[GTFS_LANDING]`, `max_active_runs=1`, `catchup=False`, a `feed_date` param defaulting to `None`, and tags `["gtfs", "bronze"]`. Then six `@task.bash` tasks with `task_id=f"bronze_{table}"` and `pool="spark"`, plus `retries=2` and `retry_delay=timedelta(minutes=10)`. Each returns `shlex.join(spark_submit_command("/opt/airflow/src/transit/jobs/bronze.py", "--table", table, "--feed-date", feed_date))`. All six follow `feed_date`, with no order between them.
  - In `airflow-init`, after the database migration, run `airflow pools set spark 1 "One Spark job at a time on the VM"`.
