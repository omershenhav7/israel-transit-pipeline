# Silver Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** build six typed, bus-only silver Delta tables from each day's bronze tables, with bad rows moved to a rejects table and a 0.1% limit, one Airflow task and one `spark-submit` per table.

**Architecture:** the table rules live in `src/transit/silver.py` as plain functions over Spark DataFrames, tested with local Spark and local Delta paths. Retention moves from `bronze.py` to a shared `src/transit/lakehouse.py`. `src/transit/jobs/silver.py` is the `spark-submit` entry point for one table and one day. `gtfs_build` gets six `silver_*` tasks in the `spark` pool, each downstream of the bronze tasks it reads.

**Tech Stack:** PySpark 4.2.0, delta-spark 4.4.1, Airflow 3.3.2, pytest. Everything runs in the `transit-airflow:latest` image.

**Spec:** [`docs/stage-3-silver.md`](../../stage-3-silver.md)

## Global Constraints

- Six tables, with the silver column names, types and order from the spec's tables. Each table then ends with `feed_date` (`date`, the partition column) and `_loaded_at` (`timestamp`).
- Paths under a lakehouse root (`s3a://<bucket>` in production, `tmp_path` in tests): `<root>/bronze/<table>`, `<root>/silver/<table>`, `<root>/silver/_rejects`.
- Bus membership comes **only from bronze** partitions of the same `feed_date`, never from silver. Non-bus rows are dropped, never rejected.
- A row is judged on its own columns only. Never reject because of another table (no cascades, no unknown-reference rejects).
- "Required" column: empty or malformed rejects the row. "Optional" column: empty or malformed becomes null. All rows sharing a key are rejected with `duplicate_key`.
- Reject limit: rejected ÷ (kept + rejected) ≤ `0.001`. Above it: write the rejects, delete the day's silver partition of that table, raise.
- Writes use `replaceWhere feed_date = '<date>'`, and for rejects `` feed_date = '<date>' AND `table` = '<table>' ``.
- Retention: same rule as bronze (7 days before today in `Asia/Jerusalem`, keep the day just built, then `VACUUM`), on the table and on `_rejects`.
- **Spark 4 runs with ANSI mode on.** A plain `cast` of a malformed string raises instead of giving null. Validate with regular expressions or use `try_cast` / `try_to_date`, never a bare `cast` on unchecked text.
- Tests need no network or AWS, and run on the VM in the test image against a copy of the branch (as in stage 2), never in the live checkout:
  `docker compose run --rm -v "$PWD/tests:/opt/airflow/tests" airflow-cli bash -c "pip install -q pytest && python -m pytest -q /opt/airflow/tests"`.
- Work on branch `stage-3-silver`. Commit after each task. Don't push without asking.

## Review Focus

1. **Malformed numbers and dates under ANSI mode.** `stop_lat = "abc"`, `start_date = "20261340"`, `stop_sequence = "1.5"` must reject (or null, for optional columns), not crash the job. Test: `test_malformed_values_reject_not_crash` in Task 3.
2. **A required column that is empty on a row whose key is duplicated.** Each row gets exactly one reason. A bad row keeps its own reason, and `duplicate_key` applies to the remaining rows of a key that appears more than once among the table's bus rows. Test: `test_one_reason_per_row` in Task 3.
3. **A rebuild with zero rejects after a run that had some.** The day's old rejects for that table must be gone. Test: `test_rebuild_clears_old_rejects` in Task 4.
4. **A rebuild that goes over the limit after an earlier good build.** The earlier silver rows for that day must be deleted, not left behind. Test: `test_over_limit_deletes_existing_partition` in Task 4.
5. **A destination with a `-` in its name**, and a destination whose suffix doesn't match the route's own direction and variant. Test: `test_long_name_cities` in Task 2.

### Task 2: Column parsers

**Files:**
- Create: `src/transit/silver.py`
- Create: `tests/test_silver_parsers.py`

**Interfaces:**
- Produces, in `src/transit/silver.py`, Spark column functions (each takes and returns `pyspark.sql.Column`):
  - `gtfs_seconds(c) -> Column`: `int` seconds for `^(\d{1,2}):([0-5]\d):([0-5]\d)$`, else null.
  - `route_desc_parts(c) -> Column`: a struct `(line_id, route_direction, route_variant)` from `^(\d+)-([123])-(.+)$`, else null.
  - `long_name_parts(long_name, direction, variant) -> Column`: a struct `(origin_name, origin_city, destination_name, destination_city)`, or null when the text doesn't have exactly one `<->` or the right side doesn't end with `-` + direction + variant.
  - `stop_desc_parts(c) -> Column`: a struct `(street, city, platform, floor)`, each trimmed with empty becoming null. All null when the text doesn't match.

`long_name_parts` algorithm: split on `<->` (exactly two parts). Remove the suffix `"-" + direction + variant` from the right side. Then, for each side, the city is the text after the last `-`, and the name is the text before it. A side with no `-` gives name = the whole side and city = null. Trim both, and turn empty into null.

`stop_desc_parts` pattern: `^רחוב:(.*)עיר:(.*)רציף:(.*)קומה:(.*)$`.

### Task 3: Bus filter and table rules

**Files:**
- Modify: `src/transit/silver.py`
- Create: `tests/test_silver_rules.py`

**Interfaces:**
- Consumes: Task 2's parsers, and `TABLES` from `transit.bronze` (bronze column names)
- Produces, in `src/transit/silver.py`:
  - `SILVER_TABLES: dict[str, tuple[str, ...]]`, the silver data columns of the six tables in the spec's order (without `feed_date` / `_loaded_at`)
  - `KEYS: dict[str, tuple[str, ...]]`: `routes` `("route_id",)`, `trips` `("trip_id",)`, `stop_times` `("trip_id", "stop_sequence")`, `stops` `("stop_id",)`, `operators` `("operator_id",)`, `calendar` `("service_id",)`
  - `SOURCES: dict[str, tuple[str, ...]]`, the bronze tables each job reads, own table first: `routes` `("routes",)`, `trips` `("trips", "routes")`, `stop_times` `("stop_times", "trips", "routes")`, `stops` `("stops", "stop_times", "trips", "routes")`, `operators` `("agency", "routes")`, `calendar` `("calendar", "trips", "routes")`
  - `bus_rows(table: str, bronze: dict[str, DataFrame]) -> DataFrame`: the rows of `bronze[SOURCES[table][0]]` that are bus rows by the spec's "Which rows are buses" table, with the bronze columns unchanged (left semi joins)
  - `clean(table: str, df: DataFrame) -> DataFrame`: takes `bus_rows` output and returns one row per input row, with the `SILVER_TABLES[table]` columns, then `_reason` (`string`, null when kept) and `_raw` (`string`, `to_json` of the bronze data columns)

Reason codes (*plan's call*, the spec leaves them to the builder):
- `missing_<bronze column>` for an empty required column
- `bad_<bronze column>` for a malformed required column. `route_long_name` counts as malformed when `long_name_parts` gives null.
- `departure_before_arrival`, `start_after_end`, `duplicate_key`

Each row gets exactly one reason: the first failing check in the column order of `SILVER_TABLES`, then the cross-column checks. Only rows with no other reason are checked for `duplicate_key`, and a key counts as duplicated when it appears more than once among **all** the table's bus rows.

  - `test_routes_clean`: a valid route gives every column as in Task 2's first example. Empty `route_id` → `missing_route_id`; `route_desc = "11337-9-0"` → `bad_route_desc`; a long name with two `<->` → `bad_route_long_name`; empty `route_short_name` → kept, with a null `line_public_number`.

### Task 4: Building one table for one day

**Files:**
- Modify: `src/transit/silver.py`
- Create: `tests/test_silver_build.py`

**Interfaces:**
- Consumes: `bus_rows`, `clean`, `SOURCES`, `SILVER_TABLES`; `cleanup` and `table_path` from `transit.lakehouse`; `load_table` from `transit.bronze` (to create bronze fixtures in tests)
- Produces, in `src/transit/silver.py`:
  - `REJECT_LIMIT = 0.001`
  - `class SilverBuildError(Exception)`
  - `@dataclass(frozen=True) class SilverCounts: kept: int; rejected: int; non_bus: int`
  - `build_silver_table(spark, root: str, table: str, feed_date: date, today: date, loaded_at: datetime) -> SilverCounts`

`build_silver_table` follows the spec's "How one table is built" steps 1–8:
- A missing bronze table, or a partition with no rows for the day, raises `SilverBuildError` naming the bronze table and the date, before anything is written.
- `non_bus` = the bronze rows of the table's own source minus its bus rows.
- The rejects table has the columns `table`, `reason`, `row`, `feed_date`, `_loaded_at`, and is partitioned by `feed_date`.
- When the limit is exceeded, the error message holds the table, the counts and the three most common reasons.
